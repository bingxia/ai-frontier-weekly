## 一、行业/模型与产品动态

### 1. **⭐ Gemini Decisions API：为 Agent 提供专用决策接口**

- **日期：** 2026-11-11。
- **发生了什么：** Google 发布 Gemini Decision 1 和 Decisions API，通过 Gemini API/AI Studio 提供有限选项判断。支持文本、图片、音频、视频及 PDF，可对共享输入执行是非、多选和评分问题，并返回概率与置信度。官方报告在上下文不超过 16K、每请求 1—100 个问题的条件下，端到端延迟为 150—250 毫秒。
- **为什么值得关注（编辑判断）：** 工具选择、模型路由和内容分级不必每次都生成一段文字解释；专用判断接口可能减少 Agent 控制流程的延迟。
- **工程启示（编辑建议）：** 将有限选项判断与复杂规划分开。用真实失败样本校准置信度阈值，低置信度转交更强模型或人工；权限校验仍由确定性规则执行。
- **限制：** 不能把上述延迟外推到最大上下文和最大问题数量；公告中的 Google Cloud 支持仍为“即将推出”。
- **原始来源：** [Google 官方公告](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)。

### 2. Claude Fable 5.2 / Mythos 5.2：能力升级与分层开放同步推进

- **日期：** 2026-11-09。
- **发生了什么：** Anthropic 发布两款模型，宣称提升编码、推理和视觉能力。两者基于相同底层模型；Fable 配置更强的网络安全、生物领域防滥用措施，Mythos 面向通过相关验证计划的机构。官方也提供 Advisor 和 Orchestrator 使用方式。
- **为什么值得关注（编辑判断）：** 模型选择同时涉及任务能力、访问条件与编排角色，不能仅比较一个总分。
- **工程启示（编辑建议）：** 评估“普通模型执行、强模型咨询”和“强模型规划、小模型执行”两种架构，统一衡量完成率、总成本、耗时与人工修正量；升级模型时重新回归拒绝和工具调用行为。
- **限制：** 能力提升是厂商报告；Mythos 不应视作无条件公开可用。复杂演示不能替代自身业务测试。
- **原始来源：** [Anthropic 发布公告](https://www.anthropic.com/claude-fable-and-mythos-5-2)。

## 二、论文与技术趋势

### 1. **⭐ EngineAgent：让 Coding Agent 真正完成端侧推理引擎适配**

- **日期：** arXiv v1 提交于 2026-11-10；核验页面仅列 v1。
- **发生了什么：** 研究先建立推理引擎层级与依赖索引，再用已支持模型验证硬件构建、运行和调试流程。Builder 完成跨层修改，Auditor 检查完整性并推动设备端验证。作者在 12 个任务上报告 75% 端到端成功率，最强基线为 33.3%；成功需同时满足编译、设备执行及输出 logits 与参考实现一致。
- **为什么值得关注（编辑判断）：** 将软件修改、硬件调试与数值正确性放进同一个验收闭环，更接近实际模型移植工作。
- **工程启示（编辑建议）：** 先沉淀可复用的引擎索引、已验证构建命令和设备调试流程，再交给 Agent 修改新模型。将设备运行和数值误差检查设为完成条件。
- **限制：** 任务规模小，不能直接推断对任意芯片或模型有效；实验为作者报告。本期未核实可公开运行的代码仓库，因此仅列为论文。
- **原始来源：** [EngineAgent 论文与提交记录](https://arxiv.org/abs/2611.14356)。

### 2. FGSE：经验进入长期记忆前，先尝试证伪

- **日期：** arXiv v1 提交于 2026-11-10；核验页面仅列 v1。
- **发生了什么：** Falsification-Gated Self-Evolution 将经验表示为包含前提、行为变化、预期效果和验证器的假设。候选更新先进入临时状态，通过迁移、证伪和历史回归测试后，再决定提交、修订或拒绝。
- **为什么值得关注（编辑判断）：** 单次任务成功并不足以说明经验可以泛化；错误经验长期累积可能让 Agent 越用越不稳定。
- **工程启示（编辑建议）：** 为 Memory/Skill 增加候选区、反例测试、版本和回滚。评估新增记忆时同时记录收益与旧任务退化，不仅统计本轮成功率。
- **限制：** 作者结果依赖验证器及测试覆盖；本期未核实公开代码实现，不能将论文视为可直接部署的组件。
- **原始来源：** [FGSE 论文与提交记录](https://arxiv.org/abs/2611.14326)。

## 三、开源项目

### 1. **⭐ llama.cpp v1.0.0：本地推理集成应安排兼容性回归**

- **日期：** 2026-11-13 发布。
- **发生了什么：** 1.0 删除已弃用公共 API，将 NextN/推测执行相关 API 纳入 llama.h；新增 OCP FP8 KV Cache、主机内存 MoE 专家缓存，以及可配置的 CPU 分担比例。发布说明还列出服务器 SSRF、CORS、DNS 重绑定及 MCP 工具取消方面的加固。
- **开源核验：** 已读取 v1.0.0 标签下的 llama.h 源代码与 MIT LICENSE；不是仅有宣传页或待开放占位仓库。
- **为什么值得关注（编辑判断）：** 变化同时涉及下游绑定兼容性、显存压力和服务端运行边界，对本地大模型及多模态 Agent 基础设施有直接影响。
- **工程启示（编辑建议）：** 固定旧版本作为基线，在测试分支升级；回归语言绑定、上下文保存恢复、工具取消和长会话。对缓存优化同时测质量、内存峰值与延迟，避免只测 token/s。
- **限制：** 1.0 不等于全部后端自动稳定或全部模型收益相同；本期未取得周增长数据，不称“热门榜首”。开源部分仅保留本期已充分核验的一项，不为凑数加入论文占位项目。
- **原始来源：** [发布说明](https://github.com/ggml-org/llama.cpp/releases/tag/v1.0.0)、[代码](https://github.com/ggml-org/llama.cpp/blob/v1.0.0/include/llama.h)、[MIT 许可](https://github.com/ggml-org/llama.cpp/blob/v1.0.0/LICENSE)。
