# AI 周报｜2026-10-26—2026-11-01

## 摘要

本周值得关注的三个方向：**模型选择升级为多模型工作流编排；端云协同开始进入编码产品，但本地推理不等于离线；Agent 研究进一步强调证据检索和跨节点的信息权限。**

本期收录 3 条产品动态、2 篇论文和 2 个代码项目。项目按可核验的技术价值选择，不作为热度榜单。论文结果均为作者报告，未做独立复现；“工程启示”为编辑分析。资料核验截至 2026-11-02。

## 一、行业 / 模型与产品动态

### 1. Gemini 4 Carbon：强化长程工程任务，先向部分安全防御用户开放

- **日期：2026-10-28。**
- **发生了什么：** Google 宣布 Gemini 4 Carbon，重点强调编码、长程 Agent 和网络安全能力。公告说明，首批面向部分网络防御用户，再通过 Fairwind Program 扩展至可信合作方；不能据此认定普通开发者已全面可用。
- **为什么值得关注：** 模型的竞争目标继续从单轮答题扩展到跨代码库、多步骤、持续执行的工程任务。官方同时讨论作弊尝试、无证据陈述等行为指标。
- **工程启示：** 升级长程 Agent 时，应共同评估任务完成率、执行成本、恢复能力和无证据完成声明率；模型宣称更安全，也不能替代工具权限和独立验收。
- **限制：** 公告中的能力和安全改善为厂商报告；部分网络安全基准明确在未启用防护的条件下评估，不应直接等同于实际产品表现。
- **来源：** [Google 官方公告](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-carbon/)。

### 2. GitHub Copilot Fusion 正式可用：路由模型，也选择协作方式

- **日期：2026-10-28。**
- **发生了什么：** Copilot Fusion 正式可用，提供 Standard、High、Max 三档投入程度，并按任务选择 Single、Cascade、Critique 三种工作流：单模型处理、先低成本尝试再升级、生成后评审再修改。组织策略仍约束可使用的模型。
- **为什么值得关注：** “选哪个模型”与“如何组合模型”开始成为同一个产品能力。成本优化不只依靠更便宜的模型，也依靠是否需要评审和升级。
- **工程启示：** 内部模型网关可把模型路由与工作流路由分开实现，并记录每次升级原因。重点比较最终通过验收的单任务成本，避免只优化 token 单价。
- **限制：** 多模型调用会分别计费；官方基准中的成本和耗时优势不能直接推广到所有仓库与任务。
- **来源：** [GitHub：Copilot Fusion](https://github.blog/changelog/2026-10-28-route-and-orchestrate-models-with-github-copilot-fusion/)。

### 3. Copilot Fusion 试验性支持端云路由：本地执行，云端决策

- **日期：2026-10-28。**
- **发生了什么：** GitHub 开放可选的本地模型智能路由实验预览。支持的 Windows 设备可通过 Windows ML 配置 MAI Code 1.1 Flash；CLI 也支持在 Windows、macOS、Linux 上，通过本地 OpenAI-compatible 服务配置指定的支持模型。
- **为什么值得关注：** 端侧算力开始融入统一 Agent 体验。但官方明确指出：路由决策仍在云端，本地推理不让会话变成离线；普通 BYOK 模型也不会自动获得 Fusion 路由资格。
- **工程启示：** 设计端云 Agent 时，应分别明确“路由在哪里决定、哪些上下文离端、推理在哪里执行、断网如何降级”。敏感任务需要独立的本地强制策略，不能只依赖自动路由。
- **限制：** 当前是实验预览，各客户端支持范围不同；不能据此认为任意本地模型都能自动参与协作。
- **来源：** [GitHub：本地模型路由预览](https://github.blog/changelog/2026-10-28-github-copilot-fusion-now-supports-selection-of-local-models/)。

## 二、论文与技术趋势

### 1. FoG：把“找到支撑证据”纳入 Agent 的训练奖励

- **日期：2026-10-27 首次提交；核验页面列示 v1。**
- **发生了什么：** FoG 面向知识图谱问答，合成带支撑三元组的问题，并用 Evidence-Coverage Process Reward 将奖励分配到首次检索到对应证据的轮次。作者在三个 KGQA 基准上报告了答案准确率和证据覆盖的改善。
- **为什么值得关注：** 正确答案可能来自模型记忆，并不代表 Agent 真正访问过所需证据。该研究把答案正确性和证据获取分开训练。
- **工程启示：** 企业 RAG/知识图谱 Agent 可同时检查答案、证据覆盖和来源有效性；训练时奖励新增有效证据，避免重复检索刷奖励。
- **限制：** 结果来自知识图谱任务，不能直接推断对开放网页或长 PDF 同样有效；证据覆盖也不自动证明完整推理正确。
- **来源：** [Clearing the FoG](https://arxiv.org/abs/2610.37405)。

### 2. TG-CI：多 Agent 隐私检查要看信息将流向哪里

- **日期：2026-10-29 首次提交；核验页面列示 v1。**
- **发生了什么：** TG-CI 将工作流表示为任务图，结合接收方已获知的信息与后续传播范围进行授权。Full-Scope 检查完整下游范围，Auto-Region 则将信息限制在允许传播的区域；作者构建了包含 144 个案例的 MAPLE-Bench。
- **为什么值得关注：** 单次传递看似合理，信息继续转发或与历史信息组合后，仍可能越过隐私边界。
- **工程启示：** Agent 间传递工件时，可附带允许接收方、用途、传播范围和来源标签；新增子 Agent 或修改任务图后，应重新检查授权。
- **限制：** 作者主实验报告未授权披露次数相对基线下降 85.8%–94.1%，同时保留基线 93.6%–96.1% 的任务准确率。这是特定实验配置的相对结果，不是生产隐私保证。
- **来源：** [Judging Before Propagation](https://arxiv.org/abs/2610.39532)。

## 三、开源项目

本节区分“许可明确的开源实现”和“代码已公开但许可待确认的项目”。没有使用 Stars 增长或榜单排名作为推荐依据。

### 1. EAT / Evolving Agent Teams：根据停滞原因重组 Agent 团队

- **日期：关联论文于 2026-10-27 首次提交，页面列示 v1；代码状态于 2026-11-02 核验。**
- **发生了什么：** EAT 用监督 Agent 分析失败或性能停滞，再调整团队角色、提示词和工作阶段；跨轮文件系统保存经验、历史和产物。已核验公开仓库及实际启动脚本，主仓库采用 Apache-2.0 许可。
- **为什么值得关注：** 它提供了“动态改组团队”的实现参考，适用于有明确评测器的代码和性能优化任务，而不是简单增加并发 Agent 数量。
- **工程启示：** 可借鉴“监督者配置团队—工作 Agent 修改代码—独立评测器打分”的职责划分，并为角色分工、文件所有权、预算和每轮成绩留下记录。
- **限制：** 论文报告在扩大 token 预算后，生成的 MLA 解码内核平均达到 FlashInfer 基线的 1.2 倍速度，但 47 个工作负载中仍有 11 个落后。框架运行依赖 Claude Code 等环境；任务集中的第三方代码还需遵守各自 NOTICE。本次未执行复现。
- **来源：** [论文](https://arxiv.org/abs/2610.36848)、[代码仓库](https://github.com/caoshiyi/EAT)、[实际启动脚本](https://github.com/caoshiyi/EAT/blob/main/agent_team/launch_stateless.sh)、[许可](https://github.com/caoshiyi/EAT/blob/main/LICENSE)。

### 2. UMI-Live：双手示范采集到训练数据的完整管线，许可待确认

- **日期：关联论文于 2026-10-29 首次提交，页面列示 v1；代码状态于 2026-11-02 核验。**
- **发生了什么：** UMI-Live 将双手手持设备的视频、位姿和夹爪状态组织为机器人学习数据。公开仓库包含设备端、处理服务、共享核心及数据质量相关目录；项目页提供约 40 小时、三个任务的数据入口。
- **为什么值得关注：** 亮点是把同步采集、后台重建、质量检查和数据发布串成可恢复的工程流程，减少从演示到 VLA 训练之间的人工整理。
- **工程启示：** 多模态数据平台应把时间同步、坐标系、传感器校准、处理阶段状态和失败恢复作为核心数据契约，保留原始数据与派生数据的对应关系。
- **限制：** “无需采集环境标定”不代表设备完全无需校准，仓库仍有相机和夹爪校准流程。实验每条件仅十次试验、一个训练种子，不能据此判断广泛泛化能力。虽然论文称其开源，本次未在所查主仓库根目录和说明中确认仓库级许可；因此仅确认代码公开，不认定可自由商用或再分发。本次未运行硬件复现。
- **来源：** [论文](https://arxiv.org/abs/2610.39385)、[项目页](https://umi-live.github.io/)、[代码仓库](https://github.com/AfterQuery-Research/umi-live)。
